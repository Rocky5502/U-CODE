\abstract{%
Coding agents may generate plausible software patches while missing defects that
are costly to discover after deployment. Under bounded computing resources, an
agent must decide whether to generate another patch, retrieve relevant context,
run diagnostic tests, inspect code statically, attempt a repair, or stop.
Existing research has examined uncertainty-based code revision, software-agent
search, selective action verification, and multi-objective configuration
optimization. What remains to be established is whether jointly modeling the
value of acquiring different forms of verification evidence improves the
reliability of patches ultimately released at matched resource budgets.
We formulate this question as a risk-constrained partially observed sequential
decision problem, distinguishing the information value of diagnostics from the
candidate-space gains of generation and repair. We specify selective-error and
coverage estimands, budget-matched policy controls, and a leakage-resistant
evaluation using independently checked repository tasks. This version presents
a research protocol and an analytical reference implementation only; real-world
reliability gains and statistical risk guarantees have not yet been established.
}

\keywords{search-based software engineering, coding agents,
uncertainty calibration, evidence acquisition, selective verification,
budget-constrained optimization}

\section{Introduction}\label{sec:introduction}

Repository-level coding agents are evaluated on executable software tasks,
including real-world issue resolution \cite{jimenez2024swebench,yang2024sweagent}.
However, a tool call that consumes tokens or test execution time may produce
new code, reveal diagnostic evidence about existing code, or both. Treating
every call as additional candidate search obscures these different
causal and computational effects.

The relevant prior methods already include Monte Carlo tree search for repair
\cite{antoniades2025swesearch}, multi-objective optimization of agent
configurations \cite{gong2025ga4gc}, replay-based test-time scaling
\cite{ding2026swereplay}, and selective action verification
\cite{zou2026sweverifier}. We therefore do \emph{not} claim the first
uncertainty-aware or multi-objective coding-agent search.

Our falsifiable question is whether a \emph{calibrated, risk-aware allocation
across heterogeneous diagnostics and generative interventions} can improve
independently verified full-task success under the same vector resource
budget, without concealing failures through excessive abstention.
The present paper is a \emph{pre-experimental research draft}, not a report
of measured improvements.

\section{Related Work and Novelty Boundary}\label{sec:related}

\subsection{Repository-level agents and search}
We distinguish \emph{generating additional candidate patches} from
\emph{acquiring evidence} about existing candidates. SWE-bench provides
issue-resolution tasks with programmatic evaluation, and SWE-agent
establishes an interface for repository editing and test execution
\cite{jimenez2024swebench,yang2024sweagent}. These precede U-CODE.

SWE-Search applies Monte Carlo tree search and iterative refinement to
software repair \cite{antoniades2025swesearch}. SWE-Replay reuses
trajectories and intermediate search states to reduce redundant
test-time computation \cite{ding2026swereplay}. GA4GC performs
multi-objective optimization of agent prompts/configuration
\cite{gong2025ga4gc}; FormulaCode benchmarks optimization over
large codebases \cite{sehgal2026formulacode}. These methods
establish that agent search, compute allocation, and Pareto
optimization are not individually novel. U-CODE must beat
cost-matched search and score-free reuse, not merely a single
generation baseline.

\subsection{Selective and trained verification}
SWE-Verifier selects when to verify coding-agent actions, making
selective verification a close comparator \cite{zou2026sweverifier}.
ExecCritic trains testing and repair agents
\cite{tao2026execcritic}; independent work questions whether more
agent-generated tests improve resolution \cite{chen2026rethinktests}.
The number of tests and their independent diagnostic quality are
different quantities.

The 2026 preprint \emph{Teaching Agents to Code Reliably} studies
search diversity and erroneous self-written test acceptance, then
trains agents to improve verification \cite{mohsin2026teachingagents}.
SWE-Critix post-trains a generalist verifier to assess an entire
coding-agent trajectory and explain its completion prediction
\cite{hu2026swecritix}. These approaches reinforce the need
to test the incremental value of choosing \emph{which} diagnostic
to buy next, rather than claiming first use of verification or
agent trajectory scoring. Their reported benchmark results are
external findings, not U-CODE findings.

\paragraph{Independent patch verification is not selective search.}
RETRACE reconstructs and reconciles patch-level issue
explanations using forward and backward evidence, and
reports improvements on repository issue-resolution
benchmarks \cite{li2026retrace}. Dockerless independently
inspects patches through repository exploration without
executing tests, and evaluates its verifier in a
post-training pipeline \cite{zeng2026dockerless}.
These works are directly relevant comparator designs:
U-CODE cannot claim the invention of independent
patch verification, execution-free verification,
or verifier-assisted patch repair. Its narrower,
falsifiable hypothesis concerns the \emph{decision
of when and how much} verification to purchase
relative to retrieval, candidate search and
termination, under identical hard resource limits.
Faithful external verification adapters are
preregistered as prospective comparisons, not
implemented or experimentally run baselines.

\subsection{Uncertainty, miscalibration and evidence}
AdaDec uses token uncertainty for adaptive decoding
\cite{he2025adadec}; this is distinct from post-generation,
repository-level action selection. Studies identify overconfidence
on incorrect code \cite{rathnasuriya2026overconfidence} and
cases where uncertainty-triggered self-correction is worse than
execution-feedback correction \cite{rakasi2026uncertainty}.
U-CODE consequently requires pre-outcome calibration across held-out
repositories, an uncertainty-only negative control, and a
\emph{search-without-calibration} control with identical tools and
resource budgets. A self-reported confidence is not a probability
of independent functional correctness.

\subsection{Selective risk and executable evaluation}
Conformal risk control offers statistical risk analysis under
specified loss and data conditions \cite{angelopoulos2024crc}.
A fixed predictive release threshold cannot be asserted to
certify population risk after adaptive agent decisions. We measure
both conditional wrong-release risk and release coverage and reserve
formal guarantee language for a separately justified frozen
end-to-end procedure.

SWE-rebench V2 offers multilingual repository issue tasks
\cite{badertdinov2026swerebench}. Such tasks are \emph{not}
automatically AI-authored source artifacts: fresh controlled
model-generated solutions and naturalistic agent-authored PRs
require distinct provenance, licensing and denominator definitions.
Our evaluator-only hidden tests must be unavailable to
generation, retrieval, risk estimation or search policies.

\subsection{Proposed contribution and its falsifier}
The proposed contribution is a calibrated, vector-budgeted decision
problem uniting information-producing diagnostics, candidate-producing
generation/repair, and a terminal release/abstain policy. We do not
claim first uncertainty-aware coding, first multiobjective coding
agent, first verifier-triggering controller or first use of EHVI.
The claim remains unverified until a held-out, independent oracle
shows that the resulting action policy improves verified task
success and the risk--coverage tradeoff against matched-budget
selective verification, MCTS/reuse search and no-uncertainty search.
Equal or worse performance on these comparisons is a legitimate
negative outcome, not a reason to change the benchmark after the fact.

\section{Problem Formulation}\label{sec:formulation}

\subsection{Tasks, latent acceptance and admissible observations}

Let $i$ index an immutable issue and repository snapshot. A candidate
patch $x$ has an evaluation-only correctness outcome
$Y_i(x)\in\{0,1\}$ from a sealed functional oracle. When validated
separately, a security acceptability label $G_i(x)\in\{0,1\}$
may define joint acceptability $Z_i(x)=Y_i(x)G_i(x)$; we do not assume
independence. Without a trustworthy security oracle, correctness and
scanner alerts remain separate estimands.

At step $t$, the controller sees a history
\begin{equation}
 h_t=(d_i,\mathcal{C}_t,e_t,\mathcal{F}_t,\mathbf b_t,
       \mathcal H_{<t}),
 \label{eq:state}
\end{equation}
comprising the issue, candidate patches, publicly visible qualified
diagnostics, candidate frontier, remaining resource budget, and legal
previous observations. The gold patch, independent test outputs and
evaluator-only labels $Y_i$ and $G_i$ do not occur in $h_t$.

A frozen predictor forms pre-outcome estimates
$p_t(x)=\Pr(Z_i(x)=1\mid h_t)$ and action-conditional diagnostic
observation kernels $K_a(o,h'\mid h_t)$. These are hypotheses requiring
independent calibration, not asserted probabilities of fact.

\subsection{Interventions and vector-valued budgets}

Nonterminal interventions are generation, retrieval, testing, static
analysis and repair. Terminal decisions are $\mathrm{release}(x)$ and
$\mathrm{abstain}$. In particular, abstention is not a patch.

For action $a$, let
$\mathbf c(a)\in\mathbb R^5_{\ge 0}$ encode measured token,
test-call, GPU-time, CPU-time and wall-time consumption.
A policy is feasible only if
\begin{equation}
 \sum_{t<T}c_j(a_t)\le B_j,\qquad j=1,\ldots,5.
 \label{eq:budget}
\end{equation}
A weighted cost penalty may be used for choosing between feasible
actions, but it never substitutes for these independently enforced
resource limits. Conversion rates must be preregistered.

\subsection{Selective reliability, coverage and success}

For policy $\pi$, let $D_i^\pi$ be its released patch or the abstention
symbol $\bot$. Define independent full-task success
\begin{equation}
 S(\pi)=\mathbb E\!\left[
  \mathbf 1\{D_i^\pi\ne\bot\}\,Y_i(D_i^\pi)\right],
 \label{eq:success}
\end{equation}
coverage $C(\pi)=\Pr(D_i^\pi\ne\bot)$, and selective
wrong-release risk, when $C(\pi)>0$,
\begin{equation}
 R(\pi)=
 \frac{\mathbb E[
  \mathbf 1\{D_i^\pi\ne\bot\}(1-Y_i(D_i^\pi))]}
 {C(\pi)}.
 \label{eq:risk}
\end{equation}
Any proposed $\alpha$-risk comparison must also enforce a
nontrivial preregistered coverage floor $C_{\min}>0$.
The core optimization problem is
\begin{align}
 \max_{\pi}\quad & S(\pi) \nonumber\\
 \mathrm{s.t.}\quad &
 \sum_{t<T}c_j(a_t)\le B_j\quad\forall j,\nonumber\\
 & R(\pi)\le\alpha,\quad C(\pi)\ge C_{\min}.
 \label{eq:objective}
\end{align}
These constraints describe a scientific target; satisfying them
statistically has not been established in this draft.

\subsection{Evidence value versus candidate-generation value}

For admissible terminal utility $V_0(h)$ (including option to abstain),
the ideal budget-constrained value function is
\begin{equation}
\begin{split}
 V(h,\mathbf b)=\max\bigl\{V_0(h),\quad
  \max_{a:\mathbf c(a)\preceq\mathbf b}
 \bigl[-\boldsymbol\lambda^\top\mathbf c(a)\\
 +\mathbb E_{(o,h')\sim K_a(\cdot\mid h)}
 V(h',\mathbf b-\mathbf c(a))\bigr]\bigr\}.
\end{split}
\label{eq:bellman}
\end{equation}
This is a \emph{reference formulation}, not a claim that the implemented
controller optimally solves a POMDP.

A verification-only action changes beliefs about existing patches;
its one-step expected value of sample information is
\begin{equation}
 \mathrm{EVSI}(a\mid h)=
 \mathbb E_o[V_0(T(h,a,o))]-V_0(h).
 \label{eq:evsi}
\end{equation}
By contrast, generate/repair actions may add or alter candidate patches
and must model those transition outcomes to value them.
Calculating new-candidate hypervolume improvement for a diagnostic
that adds no candidate is conceptually incorrect.

Under a strict, posterior-dependent hard risk threshold, this signed
one-step EVSI may even be negative because the restricted terminal
release rule is discontinuous; a diagnostic may move an initially
releasable candidate below the gate. The reference code preserves
negative results rather than clipping them.

The currently implemented one-step diagnostic model supports only
hypothetical binary evidence channels; it has neither estimated the
kernels from coding-agent traces nor solved the joint action-allocation
problem. Predicted Pareto hypervolume is an optional auxiliary ranking
criterion for actual candidate-producing interventions, not a proxy
for verified software correctness.

\section{U-CODE Method: Prospective Design}\label{sec:method}
The planned architecture separates generation and retrieval adapters,
an independently trained uncertainty model, an action-outcome kernel,
a cost-feasible intervention planner, a verifier in a sandbox and a
release/abstention gate. Diagnostic observations update beliefs; generate
and repair interventions update the candidate set. Any release threshold
is a policy preference until the entire adaptive procedure receives an
appropriate independent risk analysis.

\subsection{One-step vector-budget planning reference}\label{sec:planner}

We separate \emph{information-producing} actions
$\mathcal{A}_{\mathrm{obs}}=\{\mathrm{test},\mathrm{static\_analysis},
\mathrm{retrieve}\}$ from \emph{candidate-producing} actions
$\mathcal{A}_{\mathrm{gen}}=\{\mathrm{generate},\mathrm{repair}\}$.
The latter category creates or changes a patch; the former only
updates the beliefs about existing patches in this simplified reference
implementation. In a real coding workflow, retrieval may instead update
the prompt context for subsequent generation; those transitions require
an additional model and must not be silently assumed.

Let $\widehat U_0(h)$ be the terminal release-or-abstain value induced
by a frozen pre-outcome risk model and its risk threshold. A one-step
action forecast on the \emph{same terminal utility scale} is
\begin{equation}
 \widehat{\Delta}(a\mid h)=
 \begin{cases}
 \mathbb{E}_{o\mid h,a}
  [\widehat U_0(T(h,a,o))]-\widehat U_0(h),
 & a\in\mathcal{A}_{\mathrm{obs}},\\
 \mathbb{E}_{h'\mid h,a}
  [\widehat U_0(h')]-\widehat U_0(h),
 & a\in\mathcal{A}_{\mathrm{gen}}.
 \end{cases}
 \label{eq:one_step_gain}
\end{equation}
The reference controller considers only actions whose predicted gain
exceeds preregistered resource prices and obeys \emph{every} hard
budget component:
\begin{equation}
 a_t^\star=\arg\max_{\substack{a\in\mathcal A_t\\
 \mathbf c(a)\preceq\mathbf b_t}}
 \left[\widehat{\Delta}(a\mid h_t)
 -\boldsymbol\lambda^\top\mathbf c(a)\right].
 \label{eq:myopic}
\end{equation}
If this maximum is not strictly positive, it performs a terminal
release only if the predictive release gate and expected utility admit
one; otherwise it abstains. A missing candidate makes test, static
analysis and repair inadmissible. Action cost is charged exactly once,
and an action violating any one resource budget is not rescued by a
favorable scalarized price.

Our version-controlled \texttt{vector\_policy.py} is a deterministic
one-step \emph{analytical test harness} for these definitions. It accepts
hypothetical binary diagnostic likelihoods and externally supplied
generation-value forecasts; it does not learn either from real software
traces, deploy a production agent, prove Bayes optimality, or implement
the full Bellman controller in Eq.~\eqref{eq:bellman}. The visible
diagnostic test and independent held-out outcome remain separate
channels. A gate based on \emph{predicted} failure probability does not
certify conditional population risk.

\subsection{Bounded Evidence Search}\label{sec:bes}

The preceding one-step policy cannot value a diagnostic that makes
no candidate immediately releasable but enables an informative
second observation. To capture this \emph{option value}, we have
implemented \emph{Bounded Evidence Search} (BES): a
finite-horizon, branch-enumerating dynamic program over a
single active patch, a frozen pre-outcome acceptability belief
$p$, unused intervention identifiers $\mathcal A$, a five-resource
budget $\mathbf b$, and planning depth $d$. BES is an
\emph{algorithmic reference implementation}, not a fitted
repository-agent controller or a claimed first-of-kind method.

Let $U_0(p)$ be the frozen risk-gated expected
release-or-abstain utility, and let $K_a(o,p'\mid p)$ be an
externally supplied distribution over admissible visible
action observations and successor \emph{predicted} patch
acceptability. Generation and repair can replace the active
candidate; diagnostics alter its belief without creating
another code candidate. An unusable generation result keeps
the incumbent candidate, when one exists. We compute
\begin{align}
V_0(p,\mathbf b,\mathcal A)
&=U_0(p),\label{eq:beszero}\\
V_d(p,\mathbf b,\mathcal A)
&=\max\Bigl\{U_0(p),\nonumber\\[-1mm]
&\quad\max_{\substack{a\in\mathcal A\\
 \mathbf c(a)\preceq\mathbf b}}
\Bigl[-\boldsymbol\lambda^\top\mathbf c(a)
 +\sum_{o,p'}K_a(o,p'\mid p)
 V_{d-1}(p',\mathbf b-\mathbf c(a),
 \mathcal A\setminus\{a\})\Bigr]\Bigr\}.
\label{eq:bes}
\end{align}
At each replanning step, BES purchases the chosen feasible
action only after the input probabilities and cost vector
have been fixed. The subsequent visible observation updates
the local posterior and removes the spent action ID. Hidden
evaluation outcomes are never valid policy inputs.

\paragraph{Bounded correctness property.}
For finite, correctly specified transition scenarios and
the stated one-candidate and one-use restrictions,
Eq.~\eqref{eq:bes} is the optimal finite-horizon expected
terminal utility \emph{within that restricted decision model}
by backward induction. Likewise, budget nonnegativity
holds branchwise: the recursion subtracts a resource
vector only when each of its components is affordable.
Neither statement establishes general POMDP optimality,
model calibration or statistical risk control. Worst-case
tree enumeration grows exponentially with planning depth.
The software currently limits the action set to ten,
horizon to four, and memoized states to $30{,}000$.

\paragraph{Analytical need for look-ahead.}
Consider a hypothetical patch with $p=0.5$ and a release
gate requiring $p\ge0.9$; correct/incorrect releases have
utilities $+1$ and $-1$. Two conditionally independent
tests each have sensitivity and specificity $0.8$
and a scalar planning price of $0.01$. A single positive
test yields posterior $0.8$, still below the release
threshold; the one-step policy abstains. Two positive
tests yield posterior $16/17$ and occur jointly with
probability $0.34$. Their expected positive terminal
utility is $0.30$; testing a second time only following
a first positive costs $0.01+0.5(0.01)=0.015$ in
expectation. BES accordingly attains \emph{hypothetical}
two-step expected net utility $0.285$ within this
specified toy model. This is an analytical regression
fixture, \emph{not} a real coding-agent result.

\paragraph{Critical assumptions and limits.}
Multiple binary diagnostic results are assumed
conditionally independent given latent acceptability
\emph{only when the caller explicitly enables this
simplification}; correlated tests require a genuinely
history-conditional observation model. Generation and
repair currently replace, rather than archive, candidate
patches. Retrieval is modeled as evidence on an existing
candidate, not as a pre-generation context-improvement
action. Every action ID is usable at most once in a
planning session. These are explicit methodological
limits. Strong comparable baselines include the existing
one-step controller, an uncertainty-removed look-ahead
planner, and externally established selective verifier
and search methods \cite{antoniades2025swesearch,zou2026sweverifier}.
We will not claim an algorithmic improvement until
sealed-oracle evaluation on actual code establishes one.

\subsection{History-conditional evidence and correlated tests}
\label{sec:conditional}

The initial BES branch model permits sequential diagnostic
likelihood multiplication only under explicitly declared
conditional independence given latent code acceptability.
That shortcut is scientifically fragile: repeated agent-written
tests, static checkers using overlapping rules, or different
tools inspecting the same failing path may carry nearly
identical information. Two individually well-calibrated
diagnostics can therefore be \emph{jointly} misrepresented by
a product of their marginal likelihoods.

We implement a second, diagnostic-only finite-tree reference
which uses frozen history-conditioned observation channels.
For a visible diagnostic history $h_t$ and latent patch
acceptability $Z\in\{0,1\}$, let
\begin{equation}
q_{a,z}(h_t)=
  \Pr(O_a=+\mid Z=z,h_t,a),\quad z\in\{0,1\}.
\label{eq:conditional-likelihood}
\end{equation}
Unlike a single action's unconditional sensitivity and
specificity, these values depend on the already \emph{observed}
test results and their order. Given pre-outcome belief
$p_t=\Pr(Z=1\mid h_t)$, positive evidence has predictive
probability and posterior
\begin{align}
\rho_{a,+}(h_t)
 &=p_tq_{a,1}(h_t)+(1-p_t)q_{a,0}(h_t),\\
p_{t+1}^{(+)}
 &=\frac{p_tq_{a,1}(h_t)}{\rho_{a,+}(h_t)}.
\label{eq:conditional-bayes}
\end{align}
The negative branch uses complementary conditional
probabilities. Only positive-probability branches are
expanded; an observed event assigned probability zero by
the frozen kernel triggers a model-inconsistency error.
For the diagnostic subset, the BES recursion in
Eq.~\eqref{eq:bes} now tracks $h_t$ and the set of
unused action identifiers explicitly, rather than
reusing an unchanged marginal likelihood.

\paragraph{Counterexample: redundant evidence.}
Consider the hypothetical $p=.5$ and $p\ge.9$ release
gate, with two tests each having marginal sensitivity
and specificity $0.8$ and scalar planning cost $0.01$.
Under conditional independence, the first test may be
worth purchasing because two positives yield posterior
$16/17$, and the two-step plan has toy expected net
value $0.285$ (Section~\ref{sec:bes}).
Now suppose the second test is a perfect \emph{copy}
of the first: conditional on the first positive,
its positive probability is one in either latent class,
and after the first negative it is zero in either class.
The second observation then changes no posterior at all.
With the same marginal accuracies and positive cost,
a two-test plan has no incremental terminal benefit,
and the conditional controller abstains. This comparison
is a source-controlled \emph{synthetic falsification test},
not measured success on any real repository.

\paragraph{Training-data restriction.}
A train-only likelihood estimator accepts records in
which every proposed diagnostic in a small fixed panel
was scheduled before observing outcomes, regardless of
early positives or negatives. It rejects adaptive or
incomplete panels, duplicated task identities, overlap
with validation/evaluation fork-lineage groups, missing
model identity, nonchronological evidence, insufficient
class support in a visible-history context, and absent
conditional rows. For each observed context, estimates
are smoothed class-conditional frequencies; sparse
contexts are not silently backed off to independence.
A declared panel assignment is not proof that collection
was unbiased: randomized or otherwise demonstrably
ignorable ordering, correct event timestamps, and
independently sealed oracles need separate audit.
The current implementation has \emph{no real fitted
conditional kernels}, and the complete-panel cost can
itself be impractical at repository scale.

\paragraph{Scope.}
The history-conditioned variant handles diagnostic
decisions for one fixed candidate; it is not yet a
unified history-dependent generator/repair model,
nor a demonstrated calibrated multiobjective planner.
It will support an ablation comparing explicit
dependence handling against unconditional-likelihood
BES, with the same budgets and held-out task histories.
A performance improvement is not assumed.

Strong equal-budget baselines include no search, fixed testing, random
tools, cost-only allocation, uncertainty-only regeneration,
search without uncertainty, raw-risk and calibrated-risk ablations,
and comparators resembling SWE-Search and SWE-Verifier as resources permit.
A credible cross-policy experiment must isolate the predictor,
candidate pool and held-out evaluation oracles.

\section{Dataset Provenance and Experimental Design}\label{sec:dataset}
The discovery pool contains 120 GitHub PR candidate links, not 120
independently attributable or executable AI-authored patches.
The current repository ledger records ongoing path-level provenance
screening. No naturalistic sample is promoted to a correct
AI-generated patch on merge status alone. Rights and independent
execution checks are mandatory.

For a controlled experiment, we plan repository/fork-lineage splits,
immutable pre-fix snapshots, separately sealed post-policy evaluation
oracles, task-paired policy runs and measured token/test/GPU/CPU/wall
budgets. Model revisions and calibration datasets must be pinned.
Only runnable, rights-cleared and leakage-safe tasks will be used.

\subsection{Completed PR-discovery metadata screen}\label{sec:prscreen}

For feasibility assessment, we froze a search-derived list of
$120$ GitHub pull-request links, sampled as ten results in
each of twelve \emph{repository-primary-language} search
strata under the query condition
\texttt{author:copilot-swe-agent[bot]}, merged PRs.
All $120$ links were attempted through read-only public
metadata interfaces on 24--25 October 2026. Of these,
$119$ had retrievable PR and changed-file metadata;
one link returned an inaccessible/404 PR. The discovered
search account identifies the public PR association,
\emph{not} a verified percentage of autonomously
generated lines or the language actually changed.

of each changed file. Twelve observed repository
records were forks. Excluding IDE/build outputs
and differentiating changed-file from repository

initial screening estimate. These observations
are descriptive evidence about the \emph{fixed
discovery sample}; they are not a representative

distribution-wide agent success.

\emph{No PR in this discovery pool has yet passed}
line-level generation attribution, file-rights
review, independently reconstructed pre-fix task,
isolated execution and evaluator-only sealed
correctness tests. Accordingly, the number of
independently qualified experimental tasks
remains \textbf{zero}. The count of metadata
source-path candidates must never be reused as the
denominator for model-effectiveness claims.
The timestamped changed-file and immutable
revision records, including the retrieval failure,
are maintained as versioned JSONL artifacts; an
offline aggregation command recomputes the
exact attrition table and a separate conservative
manual-review queue. That queue \emph{cannot}
mark a task eligible for experimental execution.

\paragraph{Limits of the source-and-test-path filter.}
A further read-only patch/commit inspection of two
first-pass manual leads illustrated why test file
presence is not an independently validated oracle.
In Skell PR~88, a Go source change concerned
archive symlink/path validation and a modified
unit test replaced a host-specific directory
literal. That source change warrants a security
review and independently replayed cross-platform
checks before admission. In onnx-light-viewer
PR~120, a Python example generator changed ONNX
helper imports and a JavaScript test examined
source-text patterns: this verifies the import
alias pattern, \emph{not} independent functional
correctness of generated ONNX graphs. Public
commit metadata in both cases included bot
authorship with human co-author trailers.
Both repositories exposed root Apache-2.0
license texts, but we did not approve
changed-file rights or execute either PR.
Their immutable source paths, commit identifiers
and human--agent metadata are archived separately
from the 120-link discovery screen. Neither case
is yet an executable evaluation unit.

\paragraph{Prospective policy--evaluator information boundary.}
To prevent evaluation contamination, we register
prospective pilots with an immutable pre-fix task
identifier and separate policy-visible specification
references $E_i^{\mathrm{vis}}$ and evaluator-only
oracle references $H_i^{\mathrm{eval}}$.
The agent-facing metadata serializer uses an
explicit field allowlist and omits private
oracle references, oracle commitments, reviewer
metadata and tests authored in the candidate PR.
Such PR-authored tests must never be presented
as independent held-out evaluation oracles.
Distinct training and evaluation repository/fork
lineages must also be verified independently:
two different group-name strings do not prove
independence of repository ancestry. Neither
a hash nor a self-reported reviewer role
authenticates oracle secrecy. Currently our two
pilot registrations contain no sealed oracle
files, oracle commitments, signed runner
attestations or executable-task authorizations.
Software tests check metadata separation, not
host-level security isolation.

\paragraph{Specification ambiguity and nonunique gold outputs.}
Further analysis of the Go task's pre-fix
requirements reveals a threat to scientific
correctness labels. The specifications prohibit
negative loser balances and demand zero-sum
settlement, but do not uniquely determine the
winner of an indivisible point. For an illustrative
state with capped loser deltas $(0,-5)$,
the recovered payout pool is $P=5$.
Even if we add the \emph{hypothetical stronger}
fairness condition $|w_1-w_2|\leq 1$, both
$(w_1,w_2)=(2,3)$ and $(3,2)$ satisfy
\begin{equation}
w_1+w_2=P,\quad
w_1,w_2\geq0,\quad |w_1-w_2|\leq1.
\label{eq:oracle-ambiguity}
\end{equation}
For even $P$ the near-equal allocation is
unique, while for odd $P$ two allocations
remain possible. This basic analytical witness,
also covered by first-party exhaustive property
tests, is not a correctness finding about
the external Go patch. An independent domain
reviewer must authorize whether either output
is valid or a particular tie-break is required.
Any score-only microtask must also be disclosed
as a narrower evaluation than the original
PR's transactional database settlement.

\paragraph{Recent benchmark integrity evidence.}
SWE-Bench Pro Verified identifies the dangers
of benchmark reward hacking, answer leakage
and incorrectly scoped repository tests
\cite{zheng2026sweproverified}.
Consequently our source-path metadata audit
must not be promoted to executable tasks
without independently reviewed test
requirements and evaluator isolation.
PR-authored tests may help characterize
the source task, but cannot by themselves
establish fresh evaluation correctness.

\subsection{Training-only diagnostic likelihoods}\label{sec:diag-fit}

Let $O_i^a\in\{+,-\}$ represent one visible diagnostic result for
action $a$, recorded \emph{before} the evaluator-only acceptable-patch
outcome $Z_i\in\{0,1\}$. The same predeclared target must be used
throughout a comparison; in the absence of a validated security oracle,
$Z_i$ represents functional correctness only. For a given pinned
model and action, training-only smoothed diagnostic estimates are
\begin{align}
\widehat{\mathrm{Se}}_a
&=\frac{n(Z=1,O^a=+)+\eta}{n(Z=1)+2\eta},
\label{eq:sensitivity}\\
\widehat{\mathrm{Sp}}_a
&=\frac{n(Z=0,O^a=-)+\eta}{n(Z=0)+2\eta}.
\label{eq:specificity}
\end{align}
These class-conditional frequencies are distinct from a calibrated
\emph{prior} probability that the patch is correct. A pretrained or
fitted prior must be assessed independently before Bayes updating.
No conditional independence is assumed between successive diagnostics.

The present training-only implementation rejects overlapping
train/validation/evaluation repository-lineage groups,
cross-model or cross-action pooling, duplicated task identifiers,
underrepresented binary classes, and diagnostics timestamped after
the independent oracle. These are \emph{engineering leakage checks},
not proof that a third-party test was hidden or independently run.
The current defaults (smoothing $\eta=1$, five training instances per
class and at least two training lineages) are software validation
settings, not an empirical-power determination. We have not fitted
this method to observed coding-agent data or established calibration.

\paragraph{Evaluation contract.}
Train and freeze the conditional diagnostic likelihoods and
patch-success prior without held-out labels, compare matched
token/test/GPU/CPU/time budgets and report both unconditional
independent verified success and wrong-release risk at a
pre-registered minimum release coverage. Selection bias from
adaptive testing and repository distribution shift require
specific analysis rather than assuming exchangeability or
distribution-free risk control.

\subsection{Uncertainty-blind baseline and action parity}
\label{sec:blind-control}

As an initial \emph{negative-control implementation},
we constructed a fixed-schedule controller with the
same admissible action \emph{types} as the one-candidate
BES reference: generate a candidate, retrieve context,
run tests or static analysis, repair, and then
release or abstain. The controller receives only
visible candidate-content hashes, observed
diagnostic outcomes, a frozen action priority
schedule and the residual five-resource vector.
No predicted patch success, diagnostic
sensitivity/specificity, Bayesian posterior,
evaluation-only gold verdict or verifier
training label can appear in the typed action
catalog. All actions are charged separately
against the same physical vector budget; after
a repair changes a candidate, old diagnostic
observations are invalidated rather than
silently reused as evidence about new code.

This negative control has an intentionally
simple terminal policy: one or more preregistered
positive visible \emph{test} observations may
trigger release; a failed diagnostic triggers
a predetermined repair if available, otherwise
abstention. Retrieval or static-analysis positivity
alone cannot certify correctness. A positive
agent-visible test is \emph{not} an independent
functional oracle, and thus release is never
automatically counted as verified success.
A fixed schedule cannot represent the strongest
uncertainty-free search policy: richer heuristic
search, tuned action allocation and verifier-based
competitors remain mandatory before a claim
of improved coding-agent performance.

We additionally implemented a \emph{pre-execution
action-parity audit}. If $\mathcal A_U$ and
$\mathcal A_B$ are the two controllers'
advertised actions, the audit requires
\begin{equation}
 \bigl\{(id_a,\mathrm{type}_a,
       \mathbf c_a):a\in\mathcal A_U\bigr\}
 =\bigl\{(id_a,\mathrm{type}_a,
       \mathbf c_a):a\in\mathcal A_B\bigr\},
 \qquad \mathbf B_U=\mathbf B_B .
 \label{eq:action-parity}
\end{equation}
The canonical sorted action IDs, types,
cost vectors and original budget are
hashed for reproducibility. BES-only
forecast probabilities and blind-only
frozen priority ranks are omitted from
this shared opportunity digest. This is
a necessary \emph{static} fairness check;
it cannot prove equal model inference,
oracle quality, action implementations,
tool execution costs or runtime access.
The companion first-party synthetic trace
demonstrates generation, retrieval,
failed testing, repair and subsequent
release without executing a third-party
repository or observing an independent
oracle. It does not establish a performance
difference.

\subsection{Optimized uncertainty-free search comparator}
\label{sec:optimized-search}

To avoid attributing ordinary search gains to Bayesian uncertainty
modeling, we have additionally implemented a separate
\emph{uncertainty-free, depth-limited heuristic beam-search reference}
(\texttt{optimized\_search.py}). Unlike the fixed-schedule negative
control in Section~\ref{sec:blind-control}, this comparator ranks
sequences of candidate-generation, repair, diagnostic, and retrieval
opportunities subject to all five resource ceilings. It maintains
an append-only SHA256-keyed candidate archive, explicit repair-parent
lineage, and observed tool results attached to the corresponding
candidate rather than transferring evidence from a failed parent
to a repaired child. These are first-party algorithm-engineering
capabilities, not a fully reproduced real coding agent.

The baseline's permitted input is a frozen catalog of action IDs,
kinds and nominal cost vectors, current candidate fingerprints,
visible diagnostic signs, the previously attempted action IDs,
and the remaining five-resource budget. In particular it receives
no fitted acceptability prior, confidence estimate, posterior,
sensitivity/specificity, expected correct-patch value, future
diagnostic outcome, evaluator-only test or gold patch. Given
a candidate-dependent visible state $h_t$, a predeclared vector
of nonnegative heuristic action weights $\boldsymbol\omega$, a
planning-only price vector $\boldsymbol\lambda$, and a candidate
action sequence $P=(a_1,\ldots,a_H)$, its surrogate objective is
\begin{equation}
 Q_{\mathrm{blind}}(P\mid h_t)
 =\sum_{k=1}^{H}\left[
 \omega_{\mathrm{type}(a_k)}
 +b_{\mathrm{vis}}(a_k,h_t)
 +b_{\mathrm{div}}(a_k,P_{<k})
 -\boldsymbol\lambda^\top\mathbf c(a_k)\right],
 \label{eq:blind-heuristic-beam}
\end{equation}
where $b_{\mathrm{vis}}$ rewards an actionable repair after
\emph{visible} failure or a first testing opportunity, and
$b_{\mathrm{div}}$ rewards diversification of action types.
Neither bonus contains an estimate of latent correctness.
Every sequence must respect action-ID single-use, a bounded
candidate archive and componentwise feasibility
$\sum_{k\le H}\mathbf c(a_k)\preceq\mathbf B$.
A deterministic beam of width $W$ approximates the maximizing
path at depth $H\le4$; at each real observed result it replans.
A future generate action represents a \emph{possible}
candidate-producing opportunity and is not asserted to produce
a useful or correct patch. As a surrogate search, it is neither
globally optimal nor Bayes optimal.

A visible-test-based terminal gate can release a previously
archived candidate only when that SHA has sufficient positive
tests under a frozen threshold and no failed test or static
observation. These \emph{agent-visible} diagnostics are not
independent full-task acceptance oracles. Unsuccessful candidate
generation still consumes nominal resources and does not
silently create a solution. Resource values in this reference
remain declared planning costs, not measured GPU, CPU or wall
telemetry. Independent sandbox execution and evaluator-side
measured receipts are therefore prerequisites for an
effectiveness comparison.

For the primary matched comparison, the new first-party
\texttt{matched\_opportunities.py} expands a \emph{common}
public action--target menu before either policy scores it.
In particular, a diagnostic or repair action is offered against
every currently archived patch, while generation is target-free;
one action ID remains globally single-use regardless of target.
The uncertainty-free matched path
(\texttt{choose\_matched\_baseline}) searches this common menu
with its preregistered, probability-free heuristic, rather than
privately fixing one target before search. Its beam uses symbolic
future \emph{availability} only, not predicted patch correctness.
The earlier \texttt{choose\_search} remains for compatibility
and is not the matched primary comparator.

The canonical public opportunity digest includes action ID,
kind, target, nominal resource reservation, candidate ancestry,
archive capacity, attempted IDs and remaining budget, excluding
all private likelihoods, priors and oracle fields. This is stronger
than matching an initial action catalog, but still does not
establish matched physical tool execution, prompt/model/seed
access, or independent outcome evaluation. Neither a beneficial
effect nor the superiority of uncertainty modeling is
presupposed; the baseline may outperform U-CODE. All current
tests are synthetic engineering checks, not Results observations.

\subsection{Shared candidate ledger and bounded joint archive search}
\label{sec:shared-archive}

Both primary policy references now use a typed, immutable
policy-neutral execution ledger of real patch SHA256 identities,
generation/repair ancestry, candidate-bound \emph{visible}
diagnostic outcomes, globally single-use tool identifiers and
remaining five-dimensional resources
(\texttt{matched\_session.py}). The ledger exposes no gold label,
correctness prior, posterior or diagnostic likelihood.
\texttt{matched\_opportunities.py} constructs the same feasible
action--target set $\Omega(s)$ for either policy: one target-free
generation alternative, or one diagnostic/repair alternative
per archived candidate, subject to capacity, used IDs and
componentwise affordability. The pre-run audit additionally
requires equal initial tool catalog, archive and budget.
A public SHA256 menu digest excludes policy-private predictions.

We retain \texttt{conditional\_archive.py} as a backward-compatible
\emph{per-patch} reference, but the new
\texttt{joint\_conditional\_bes.py} implements finite-horizon
\emph{whole-archive} dynamic programming. A planning state is
\begin{equation}
 s_t=\left(\mathcal C_t,
 \{p_x,r_x,h_x\}_{x\in\mathcal C_t},
 \mathcal A_t,\mathbf b_t\right),
 \label{eq:joint-archive-state}
\end{equation}
where $p_x$ is the pre-outcome acceptability belief for patch
$x$, $r_x$ is its frozen diagnostic profile, $h_x$ is
\emph{only its own} visible diagnostic history,
$\mathcal A_t$ contains globally available action IDs, and
$\mathbf b_t$ is the remaining hard resource vector.
The stopping value over the full archive is
\begin{equation}
 V_0(s)=\max\left\{0,\max_{x\in\mathcal C_t}
 U_{\mathrm{rel}}(p_x)\right\}.
 \label{eq:archive-stop}
\end{equation}
For a fixed finite depth $d\le4$, our analytical recursion is
\begin{equation}
 \begin{split}
 V_d(s)=\max\Bigl\{V_0(s),\;
 \max_{\omega\in\Omega(s)}
 \bigl[-\boldsymbol\lambda^\top\mathbf c(\omega)\\
 +\sum_{z}P_{\theta}(z\mid s,\omega)
 V_{d-1}\bigl(T_{\theta}(s,\omega,z)\bigr)\bigr]\Bigr\}.
 \end{split}
 \label{eq:joint-archive-bellman}
\end{equation}
The branch kernel is history-conditional for diagnostics and
target-profile/history-conditional for repair; all quantities
are externally supplied, frozen \emph{hypothetical} models.
The recursion can test multiple different archived patches,
retain a repaired parent, and generate a symbolic candidate
before planning a later diagnostic on that candidate.
This is exact \emph{only within the supplied finite,
candidate-factorized transition model and state cap}, not
a solution of the general coding-agent POMDP. The approach
is conceptually related to Bayes-adaptive planning
\cite{ross2011bayesadaptive} and sequential value of
information across alternatives
\cite{mes2011hierarchicalkg}, without inheriting their
distributional assumptions or guarantees.

Future patches in the Bellman tree have typed
\emph{symbolic branch identities}, never invented real SHA256
values. Only an actual executor-produced content SHA may
enter the shared ledger, and after real generation a separately
frozen pre-outcome scorer must assign that \emph{actual}
patch's prior/profile before replanning. Parent evidence is
not copied to its child. Every publicly feasible opportunity
must have the required frozen conditional likelihood row or
target-specific producer forecast on each reachable branch;
missing coverage raises an error rather than silently
reducing the treatment's menu. The finite model presently
factorizes evidence by candidate: sibling-patch dependence
from a common task/model latent factor remains unmodeled,
a substantive threat to validity.

The reference planner reserves \emph{nominal} action vectors;
the shared ledger separately checks \emph{caller-reported}
five-dimensional consumption and rejects replays,
inconsistent receipts and illegal lineage. These are
deterministic bookkeeping properties, not independent
physical measurement or hard sandbox enforcement. A
production runner must enforce caps \emph{during} execution
and independently meter tokens, test calls, GPU, CPU and
wall time. Joint-planner computation itself must be
charged to the same CPU/wall budget or covered by a
preregistered matched controller-compute allowance.
Neither such a runner nor independently admitted
executable tasks, sealed evaluation, train-only fitted
kernels or six-checkpoint trials has been established.
The current synthetic tests validate program behavior,
not real-world reliability, calibration or selective-risk
guarantees. The confirmatory hypothesis remains open.

\subsection{Confirmatory evaluation design and estimands}

Our primary endpoint is independently verified \emph{full-task}
success, including abstentions and unsuccessful tool runs in the
task denominator (Eq.~\eqref{eq:success}). For each frozen
task--model--seed--budget instance $i$, treatment and control policies
start at the same pre-fix snapshot and receive identical hard
resource limits. Denote the final binary success indicators
$Y_i^{(U)}$ for U-CODE and $Y_i^{(B)}$ for a preregistered
baseline. The paired treatment contrast is
\begin{equation}
 \widehat{\Delta}_{U,B}
 =\frac{1}{N}\sum_{i=1}^N
 \left(Y_i^{(U)}-Y_i^{(B)}\right),
 \label{eq:paired}
\end{equation}
where $N$ counts matched attempts, \emph{not} released patches
or seeds as independent repository instances. We will report
discordant pairs, repository/fork-lineage cluster bootstrap intervals,
the fraction of released patches, and the conditional error rate
among releases. When coverage is zero, conditional wrong-release
risk is \emph{undefined}, not zero.

For the confirmatory study, a single primary budget regime and
primary U-CODE-versus-no-uncertainty-search contrast must be frozen
before inspecting independent held-out results. Secondary baseline
policies include single generation, predetermined testing,
cost-first selection, uncertainty-triggered regeneration,
selective verifier triggering, and resource-matched trajectory
search/reuse where faithful replication is feasible. We will
disclose comparator deviations rather than relabeling simplified
implementations as exact reproductions of published agents.

\paragraph{Frozen factorial assignment and evaluator receipts.}
We preregister a proposed eight-policy matrix:
U-CODE with conditional diagnostic likelihoods,
U-CODE with the simpler independent-likelihood BES,
uncertainty-free search, an uncertainty-only heuristic,
fixed testing, selective verification,
Monte Carlo tree search and trajectory replay.
The \emph{primary} comparison is conditional U-CODE
versus uncertainty-free search with identical task,
checkpoint, seed, pre-fix Git base, allowed tools,
execution environment and assigned \emph{five-component}
hard budget. External RETRACE-, Dockerless- and
SWE-Verifier-style adaptations are important
secondary fidelity-audited comparators, not
automatically presumed to be identical to the
published systems \cite{li2026retrace,
zeng2026dockerless,zou2026sweverifier}.
Every proposed policy is currently only a study
plan until its runnable implementation has been
independently verified; core reference planner
code does not constitute the complete agent or
a faithfully reproduced baseline.

The audit contract collects \emph{policy-visible}
termination receipts separately from
\emph{evaluator-only} correctness verdicts.
A release receipt must identify the exact patch
content hash and the evaluator must return
a matching hash before any correctness outcome
is joined; abstentions have no gold verdict.
Each assigned task--model--seed--budget--policy
cell must be accounted for, and all five
realized resource components must be measured
and satisfy the same assigned vector ceiling.
The validator fails when matched cells change
the base commit, model revision, tool entitlements
or execution environment. Timeouts and sandbox safety stops that release
no patch count as verified full-task success
zero but retain their original stop reason;
an infrastructure failure is reported
separately as an \emph{unknown} outcome
unless a predefined recoverability
procedure is independently approved.
No incomplete paired cell may be silently
discarded to make a treatment appear stronger.

Formally, let $R_{i,\pi}$ denote the
candidate-release event, let $Y_{i,\pi}$
be evaluator-only correctness after release,
and let $c_{i,\pi,j}$ be the measured
resource component for $j\in\{1,\dots,5\}$.
Before any performance claim we require
\begin{equation}
 \forall i,\pi,j:\quad
 0\leq c_{i,\pi,j}\leq B_{i,j},
 \qquad
 \operatorname{hash}(x_{i,\pi}^{\mathrm{release}})
 =\operatorname{hash}(x_{i,\pi}^{\mathrm{oracle}}).
 \label{eq:receipt-integrity}
\end{equation}
These checks establish \emph{metadata consistency},
not the independence or completeness of a
human-authored oracle. The actual frozen
pilot task set is currently empty, the
numerical budget values in the protocol
file are explicitly \emph{illustrative},
and there are no measured LLM-effect outcomes.

\paragraph{Bounds for incomplete execution infrastructure.}
Let $\underline s_{i,\pi}$ and
$\overline s_{i,\pi}$ be the least and
greatest independently supportable values
of full-task verified success for an
assigned run. After a complete release and
independent verdict, both equal its measured
binary correctness; after an abstention,
timeout or safety block with no release,
both equal zero. For a genuine external
infrastructure failure whose result is
unknown, set
$[\underline s_{i,\pi},\overline s_{i,\pi}]
=[0,1]$. The matched effect then admits
the transparent worst/best-case bound
\begin{equation}
 \frac{1}{N}\sum_{i=1}^{N}
  (\underline s_{i,U}-\overline s_{i,B})
 \;\leq\;\Delta_{U,B}\;\leq\;
 \frac{1}{N}\sum_{i=1}^{N}
  (\overline s_{i,U}-\underline s_{i,B}).
 \label{eq:attrition-bounds}
\end{equation}
The bounds keep every assigned task,
checkpoint, seed and resource regime
in the denominator. They are
\emph{partial-identification bounds},
not frequentist confidence intervals;
repository-lineage uncertainty must
be treated separately. The independent
evaluator contract checks that any
reported verdict matches the released
patch content digest, refuses unknown
policy/task cells, and retains timeout,
safety and infrastructure failure
counts separately. Actual experiment
data are absent, and the unit tests
exercise only synthetic receipts.

\section{Discussion and Threats to Validity}\label{sec:discussion}
Leading threats are unreliable PR authorship inference, repository-primary
versus patch-language mismatches, optional stopping, nonexchangeable
repository groups, correlated diagnostic errors, benchmark contamination,
incomplete hidden tests, distribution shift, source licensing, selective
coverage collapse and cross-study overlap. Positive and negative effects,
including false-acceptance failures, must remain visible.

\section{Conclusions}\label{sec:conclusions}
No reliability improvement, generalization effect or certified selective
risk can presently be concluded. The contribution at this stage is a
falsifiable, budget-aware evidence-acquisition research protocol.
