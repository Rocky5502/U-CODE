# U-CODE research boundaries and non-overlap

U-CODE is a distinct hypothesis-driven empirical research project. These are
**prospective boundaries**, not proof of novelty. Confirm them against each
manuscript, repository and publication policy before submission.

## Central contribution proposed for U-CODE

A calibrated, budget-aware, risk-constrained and multi-objective action-selection
strategy governing when coding agents should generate, test, retrieve, repair,
perform static analysis, or abstain, evaluated on real agent-contributed changes
and independent multilingual repository tasks.

The strongest claim (only after evidence) concerns *which verification action
to buy next*, and measured gains across budgets, languages and selective risk.

## Distinguish nearby work

- **OpenCoderX-E** focuses on correlation-aware search/verification, evidence
  graphs and candidate diversity for code generation. Avoid reproducing its
  core algorithm, using the same evaluation as if independent, or submitting
  substantially overlapping text/figures/results. U-CODE must emphasize
  independently tested uncertainty calibration and action/cost allocation.
- **CALM-SE** studies sequential interventions in coding-agent software
  engineering and repair. U-CODE should not rebrand its intervention findings
  as a new paper. Isolate task pools where feasible and keep all overlap
  explicitly disclosed, with new methods/experiments rather than duplication.
- Prior code agent and code detection studies already explore verification,
  confidence and iterative repair. The actual algorithm and controlled search
  efficacy must be shown beyond assembling existing pieces.

**Novelty gate:** before paper drafting, create a 20+ paper related-work matrix
identifying concrete equations, datasets, baselines and differences. Discuss
inclusion of the author's other unpublished submissions without violating
double-submission/anonymous-review policies. Any shared artifact must be
properly attributed and transparently documented.

## Non-overlap checklist

[ ] Distinct research hypothesis and primary estimand.
[ ] Distinct or carefully partitioned model-task evaluation instances.
[ ] Original algorithm (more than merely adding a risk score).
[ ] No recycled figures/tables/text without citation and permission.
[ ] No concurrent substantially overlapping submission.
[ ] Leakage-safe and reproducible provenance for every shared source.
[ ] Negative/null results retained in final reporting.
