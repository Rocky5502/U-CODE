## Work completed in this increment

The new `ucode.pilot_preflight.build_pilot_preflight` composes **four independent first-party registries** rather than trusting arbitrary hand-entered task IDs:

1. **Original frozen 120-PR discovery manifest and source-path metadata** are checked by the existing `validate_prospective_dossiers` routine; the two dossiers must match the PR URLs, base/head/merge SHAs, changed filenames and corresponding test paths.
2. **Evaluator-only prospective registrations** must reference the same candidate/repository/base and original PR-authored test list. Their secrecy/attestation/authorization status is not inferred from SHA strings. The policy-visible allowlist remains separate.
3. **PHP #104 and Go #43 source-era evidence** is crosschecked against pinned immutable base information and nonadmission flags. Go's documented source blob is a microtask specification *lead*, not authority to grade the entire database settlement PR; PHP's historical issue body is not an archived as-of-PR approved specification.
4. **Research protocol** must have the exact six selected model IDs, eight policy IDs, registered primary comparison, unqualified model revisions, unfrozen seeds/caps and no measured RQ outcomes. It refuses silent changes or alleged experiment completion.

The preflight returns a deterministic public-only report with blocker codes per lead, *zero* independently sealed evaluator artifacts, *zero* independently admitted tasks, and no observed primary effect. Twelve adversarial tests check altered source-era rights claims, forged gold in a public blueprint, tampered Go spec hashes, false model qualifications, ninth policy arm, wrong PR base, unregistered oracle fields, the strict CLI's blocked exit and rerun consistency. The code has **no source cloning, import of third-party code, network API, evaluation pass/fail fields, shell, GPU or runner call**.

## DRPA integration sequencing

The new [DRPA two-outcome reference](../src/ucode/dependence_robust_acquisition.py) provides mathematical candidate-action scores but **has no fitted reliability/security/validity distribution**. Its two-point score must *not* be called on these public PRs using invented labels or post-fix test outcomes and represented as a result. The activation sequence after independent admission is:

1. Freeze exact runnable task and evaluator-only oracle protocol, policy-visible context, six model revisions and task-family splits.
2. Fit and calibrate predicted reliability, safety and validity on distinct training families without looking at the held-out test labels.
3. Audit DRPA's two-point approximation and independent-validity assumption; compare against **independence EHVI and fitted joint/correlated EHVI** with the same candidate proposals and five hard caps.
4. Pre-register the exploratory DRPA variant separately from the existing eight confirmatory policy arms. The **primary preregistered comparison** remains `ucode_conditional_bes` vs `no_uncertainty_search`, full-task verified success ITT.
5. Measure actual CPU/GPU/token/test/wall spend, independent patch success, coverage and wrong releases, including timeouts, abstentions, failures and missingness. Recompute the paired effect at task-family cluster level.

## Falsifiable research boundaries

- 120 PR metadata links ≠ 120 executable tasks.
- Two reviewed source leads ≠ two authorized tasks.
- 6 model identifiers ≠ six verified runnable model checkpoints.
- 8 policy slots ≠ eight real matched experiments.
- Synthetic DRPA action reversals ≠ any measured improvement in repository correctness.
- Exact reported SHA equality ≠ authenticated independent oracle provenance.
- Missing outcome is **N/A**, not evidence of no effect.
